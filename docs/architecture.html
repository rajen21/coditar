Systems reference

Coditar Architecture & Workflow

How the pieces of the online judge fit together: two processes, three stores, and a Kubernetes sandbox that grades one testcase at a time without losing the ones that came before it.

§1

System overview

Two Node processes never talk to each other directly. The API takes requests and the worker runs code in Kubernetes — everything they share passes through Postgres or Redis, on purpose, so either one can restart, scale, or fall behind without the other noticing.

§3

Data model

Problem rows in Postgres are deliberately thin. Everything substantial — description, constraints, limits, and every testcase’s input/output/weight/hidden flag — lives in Minio as problems/{id}/meta.json and problems/{id}/testcases/{n}/input.txt | output.txt. A new problem is a folder upload plus one database row.

TableKey fieldsNotes
User id, email, password, role role is USER or ADMIN; baked into the JWT at login
Problem id, title, slug, minioPath, isActive Soft-delete via isActive; content lives in Minio
Submission userId →User, problemId →Problem, status, score, results results is per-testcase verdicts; hidden testcases are stripped before storage

§5

Kubernetes execution model

One Job runs an entire submission — every testcase in sequence, inside one pod — instead of one Job per testcase. That’s far cheaper on the k8s API, but it means every testcase shares one memory limit. What happens when one of them blows past it turned out not to be the obvious answer.

The pod itself is locked down independently of the watchdog:

  • No privilege: runAsNonRoot, fixed non-root UID, all Linux capabilities dropped, no privilege escalation, seccompProfile: RuntimeDefault.
  • No filesystem, no network: readOnlyRootFilesystem, and a NetworkPolicy that denies all traffic — submitted code cannot phone home.
  • Bounded twice: CPU/memory resources.limits from the problem’s own limits, plus activeDeadlineSeconds as a Job-level timeout backstop.
  • Cleaned up twice: the worker deletes the Job and ConfigMap in a finally block; ttlSecondsAfterFinished is the backstop if the worker itself crashes mid-grade.
§6

Security pipeline

Every request passes through the same ordered gates. Any gate can reject outright — the ones after it never run.

See README.md, HOW_TO_RUN.md and ARCHITECTURE.md in the repo for setup steps and the full API contract (Swagger at /api/docs).
